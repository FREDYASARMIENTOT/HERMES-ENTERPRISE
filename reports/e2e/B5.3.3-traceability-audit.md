### Correlation method in factory-run.yml

**CRITICAL ISSUE:** `factory-run.yml` line 393 searches for the Control Plane run using:
```bash
CP_RUNS=$(gh api ".../deploy-child.yml/runs?per_page=5" --jq '.workflow_runs[] | select(.head_sha == "'"${SHA}"'") | ...')
```

Where `${SHA}` = **Child SHA** (`708ec4dc2`). But `deploy-child.yml` runs with `head_sha` = **HERMES-ENTERPRISE HEAD SHA** (`803a9d5f`). These will **NEVER match** because:
- The Control Plane workflow runs on the **HERMES-ENTERPRISE** repository
- Its `head_sha` is always the HEAD of `FREDYASARMIENTOT/HERMES-ENTERPRISE`
- The Child SHA is a different commit in a different repository

**Consequence:** `CP_RUN_ID` is always empty in factory-run.yml output, breaking traceability between Factory and Control Plane.

**Correct approach:** Search by `deployment_id` or `correlation_id` via workflow_dispatch input payload, or use a custom API call that inspects workflow run inputs.
