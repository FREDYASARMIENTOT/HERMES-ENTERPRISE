## 2. Root Cause

**Confirmed: No startup command configured on Azure App Service.**

1. `provision-appservice.yml` creates Web App WITHOUT `--startup-file`
2. `deploy.yml` deploys WITHOUT `startup-command` parameter
3. `application.py` does NOT exist in repo root
4. Azure auto-detects `gunicorn application:app` → fails
5. App Service responds to `/` and `/health` (possibly cached/default) but API routes return 404

## 3. Correction Applied

### 3.1 provision-appservice.yml (STEP 7b)
```yaml
- name: Configure Startup Command
  run: |
    az webapp config set \
      --name "as-${APP_NAME}" \
      --resource-group "${RG}" \
      --startup-file 'gunicorn --bind=0.0.0.0:8000 --timeout 600 --worker-class uvicorn.workers.UvicornWorker Hermes.Web.backend.main:app'
```

### 3.2 deploy.yml (Deploy step)
```yaml
- uses: Azure/webapps-deploy@v3
  with:
    startup-command: 'gunicorn --bind=0.0.0.0:8000 --worker-class uvicorn.workers.UvicornWorker Hermes.Web.backend.main:app'
```

## 5. Startup Command

```
gunicorn --bind=0.0.0.0:8000 --timeout 600 --worker-class uvicorn.workers.UvicornWorker Hermes.Web.backend.main:app
```

**Rationale:**
- `gunicorn`: Production WSGI/ASGI server for Azure Linux
- `--bind=0.0.0.0:8000`: Listen on all interfaces, port 8000 (Azure default)
- `--timeout 600`: 10-minute timeout for cold starts
- `--worker-class uvicorn.workers.UvicornWorker`: CRITICAL — FastAPI is ASGI, requires UvicornWorker
- `Hermes.Web.backend.main:app`: The FastAPI app instance
