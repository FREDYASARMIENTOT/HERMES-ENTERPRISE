# Portal Endpoints Catalog

## 1. Objective

Provide complete, reusable endpoint information across:
- **Enterprise Portal** (Hermes.Web/templates/index.html)
- **Child Project Portal** (generated by RenderEngine.ps1 template)

Every endpoint displays: method, path, name, description, real status, URL, and a clickable hyperlink that opens the endpoint in a new tab.

## 2. Catalog

The catalog lives in `Hermes.Web/backend/main.py` as `ENDPOINTS_CATALOG` — a list of 11 GET endpoints:

| # | Method | Path | Name |
|---|--------|------|------|
| 1 | GET | `/api/version` | Versión del Sistema |
| 2 | GET | `/api/proyecto` | Estado del Proyecto |
| 3 | GET | `/api/workspace` | Workspace |
| 4 | GET | `/api/git` | Git Local |
| 5 | GET | `/api/github` | GitHub Remoto |
| 6 | GET | `/api/entorno` | Entorno Python |
| 7 | GET | `/api/azure` | Azure |
| 8 | GET | `/api/sqlite` | SQLite |
| 9 | GET | `/api/despliegue` | Despliegue |
| 10 | GET | `/api/telemetria` | Telemetría |
| 11 | GET | `/api/bootstrap` | Bootstrap |

Each entry includes: `method`, `path`, `name`, `description`, `is_get`.

## 3. Endpoint Metadata

Served at `GET /api/endpoints`. Returns JSON array of the catalog above. Used by the UI to render endpoint cards dynamically.

## 4. Hyperlinks

Every GET endpoint has:
- `href="/api/<path>"` — relative, no hardcoded hostname
- `target="_blank"` — opens in new tab
- `rel="noopener noreferrer"` — security best practice

**No** `javascript:` hrefs, `href="#"`, or fictitious URLs.

## 5. Dynamic Origin

Both Enterprise and Child portals rely on `window.location.origin` to construct absolute URLs at runtime. No hardcoded hostnames (`as-hermesportal.azurewebsites.net`, `as-e2eb5001.azurewebsites.net`, etc.) appear anywhere in the code.

## 6. Enterprise Portal

File: `Hermes.Web/templates/index.html`

- 11 endpoint cards in a `.endpoint-grid`
- Each card shows: method badge, path, name, description, status badge, and "ABRIR ENDPOINT ↗" button
- Status badges are updated by `setEndpointStatus()` JS function after each API fetch
- Semantic colors: success (verificado/activo/saludable/desplegado), danger (error), warning (no_disponible), info (no_configurado/no_iniciado)
- Preserves all existing functionality: health panel, metrics, project creation, traceability

## 7. Child Template

File: `tools/Modules/RenderEngine.ps1` (function `Crear-PaginaInicioProyecto`)

- Generates `index.html` for new Child projects
- 11 endpoint items in an `.endpoint-grid`
- Each item has: method badge, path, title, description, status badge, "ABRIR ENDPOINT ↗" link
- Status updated via `setEndpointStatus()` on 11 fetch calls
- All hrefs are relative — no hardcoded hostnames
- Uses `$ProjectName` and `$WebAppName` parameters for project-specific info
- Powered by Hermes Enterprise in footer

## 8. OpenAPI

The `/api/endpoints` catalog is separate from OpenAPI spec (`/openapi.json`). The catalog provides a simple, flat list of user-facing endpoint metadata. The OpenAPI spec documents all router endpoints including `/api/fabrica/*`.

## 9. Security

No secrets (tokens, passwords, connection strings) are hardcoded or exposed in:
- `ENDPOINTS_CATALOG`
- HTML templates
- RenderEngine PowerShell template

Environment variables like `HERMES_GITHUB_TOKEN` are checked for presence but never logged or exposed.

## 10. Extensibility

To add a new endpoint to the catalog:
1. Add a new entry to `ENDPOINTS_CATALOG` in `main.py`
2. Add the corresponding card in `index.html`
3. Add the corresponding item in `RenderEngine.ps1`
4. Add the `setEndpointStatus()` call in both UIs
