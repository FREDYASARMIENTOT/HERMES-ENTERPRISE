## 2. Root Cause

**Confirmed: No startup command configured on Azure App Service.**

1. `provision-appservice.yml` created Web App WITHOUT `--startup-file`
2. `deploy.yml` deployed WITHOUT `startup-command` parameter
3. `application.py` does NOT exist in repo root
4. Azure auto-detected `gunicorn application:app` → fails
5. Old `startup.sh` referenced `/home/site/wwwroot/` but Oryx extracts builds to `/tmp/<hash>/`
6. Result: App Service Running, but Hermes app never started

## 5. Startup Command

```
gunicorn --bind=0.0.0.0:8000 --timeout 600 --worker-class uvicorn.workers.UvicornWorker Hermes.Web.backend.main:app
```

**Rationale:**
- `gunicorn`: Production WSGI/ASGI server for Azure Linux
- `--bind=0.0.0.0:8000`: Listen on all interfaces, port 8000 (Azure default)
- `--timeout 600`: 10-minute timeout for cold starts
- `--worker-class uvicorn.workers.UvicornWorker`: CRITICAL — FastAPI is ASGI, requires UvicornWorker
- `Hermes.Web.backend.main:app`: The FastAPI app instance
